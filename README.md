# LeRobot Studio

Локальное desktop-приложение на Python для полного цикла работы с
[LeRobot](https://github.com/huggingface/lerobot): подготовки датасетов,
обучения VLA-моделей и open-loop тестирования checkpoint. Поддерживаются
структуры v2/v3, NVIDIA GR00T N1.7 и Being-H0.5.

## Запуск

Требуются Python 3.11–3.13, `uv` и `ffmpeg`.

```bash
git clone --recurse-submodules <адрес-репозитория>
cd markup_platmorm
uv sync --extra dev --python /usr/bin/python3.12
uv run lerobot-studio
```

Если репозиторий уже был клонирован без моделей:

```bash
git submodule update --init --recursive
```

Зависимости самих моделей тяжёлые и устанавливаются отдельно по их upstream-инструкциям:
`third_party/Isaac-GR00T/README.md` и `third_party/Being-H/Being-H05/README.md`.
Studio запускает обучение в окружении модели и показывает ошибку установки в
терминальном окне, если оно ещё не подготовлено.
Для Being-H путь к Python подготовленного окружения задаётся в поле
«Python окружения модели» его профиля гиперпараметров.

### Dry run

Для проверки всего GUI-сценария без загрузки весов и использования CUDA:

```bash
uv run lerobot-studio --dry-run
```

В этом режиме обучение симулируется, в папке запуска создаётся только
`base_checkpoint/studio_checkpoint.json`, а Action MAE / RMSE при тестировании
генерируются случайно.

Для диагностики без дисплея:

```bash
QT_QPA_PLATFORM=offscreen uv run python -m lerobot_studio.app
```

При первом запуске приложение автоматически добавляет валидные наборы из
`datasets/`. Другой набор добавляется кнопкой «Добавить датасет» — нужно выбрать
корневую папку, в которой находится `meta/info.json`.

## Возможности

- главное меню с отдельными сценариями «Датасеты», «Обучение» и «Тестирование»;
- стартовый каталог датасетов с сохранением списка между запусками;
- настройки выбранного датасета прямо в стартовом каталоге, включая
  аугментацию сразу всего набора;
- переход по эпизодам, до четырёх и более синхронных камер;
- пауза, seek, скорость 0.25–2×, mute и громкость;
- отдельные графики `observation.state`, `action` и автоматически найденных IMU-полей;
- редактирование prompt и пользовательских JSON-метаданных;
- безопасное удаление эпизода в указанную папку;
- пять аугментаций сигналов: шум суставов, плавная вариация траектории,
  time-warp, дрейф сенсора и короткие пропуски;
- десять настраиваемых визуальных аугментаций: яркость, контраст,
  насыщенность, сдвиг оттенка, гамма, размытие, шум камеры, виньетирование,
  кроп/приближение и поворот;
- создание train/validation/test в виде новых LeRobot v2.1 датасетов;
- обучение NVIDIA GR00T N1.7 и Being-H0.5 на одном или нескольких выбранных наборах;
- профили гиперпараметров «Быстрый», «Сбалансированный», «Точное обучение» и
  пользовательские профили, сохраняемые прямо из редактора;
- отдельное окно процесса с живым terminal output, loss, ETA, CPU и GPU memory;
- выбор checkpoint и тестового датасета, Action MAE / RMSE, ETA и ресурсы в
  отдельном окне тестирования.

## Модели

Исходники подключены как git submodules:

| Модель | Путь | Upstream entry point |
|---|---|---|
| NVIDIA GR00T N1.7 | `third_party/Isaac-GR00T` | `gr00t/experiment/launch_finetune.py` |
| Being-H0.5 | `third_party/Being-H/Being-H05` | `BeingH/train/train.py` |

Для GR00T Studio создаёт в папке запуска лёгкие dataset views с symlink на
данные, добавляет `modality.json` и передаёт пути штатному multi-dataset
аргументу; исходные датасеты не изменяются. Для Being-H Studio на лету
регистрирует выбранные пути и строит generic data config по `meta/info.json`,
не меняя файлы сабмодуля. Generic-конфигурация ожидает поля
`observation.state`, `action` и до 200 измерений в каждом. Для специализированных
embodiment можно выбрать другое имя `data_config` в редакторе гиперпараметров.

## Хранение изменений

LeRobot v3 объединяет несколько эпизодов в один parquet/video-шард. Чтобы не
повредить соседние эпизоды, Studio хранит prompt, пользовательские метаданные и
флаги удаления в `meta/lerobot_studio.json`. Аугментированные parquet-файлы и их
manifest находятся в `studio/`. Они сразу появляются в приложении и допускают
последующее редактирование. В списке такие эпизоды отмечены словом
«Аугментация», а в метаданных сохраняются `is_augmentation`, тип преобразования,
его параметры и индекс исходного эпизода.

Визуальные эффекты можно комбинировать. У каждого эффекта есть связанный
ползунок и поле точного числового ввода. Видео всех камер реально
перекодируется в H.264 и сохраняется в `studio/videos/`; исходные видео не
изменяются. Обработка всего большого датасета может занять продолжительное
время и потребует дополнительного дискового пространства.

При удалении таблица эпизода и его видеофрагменты сначала экспортируются в
выбранную папку. Только после успешного экспорта эпизод скрывается в Studio.

Экспорт split-набора материализует каждый эпизод отдельно и создаёт стандартные
`meta/info.json`, `meta/episodes.jsonl`, `meta/tasks.jsonl`, parquet и mp4. Видео
из общих v3-шардов извлекается через `ffmpeg`; на полном наборе это длительная
операция и требует дополнительного места.

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| Space | пауза / воспроизведение |
| ← / → | на секунду назад / вперёд |
| Shift+← / Shift+→ | предыдущий / следующий эпизод |
| ↑ / ↓ | громкость |
| M | mute |
| [ / ] | скорость |
| G | графики |
| E | prompt и метаданные |
| Delete | удалить эпизод |
| ? | показать / скрыть подсказку |
